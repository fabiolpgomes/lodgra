# Story 42.1: Email Sync Dashboard Frontend — Search-First UI

## Story

As an **admin managing 50+ properties**, I need a **scalable search-first dashboard** to monitor email synchronization health, quickly identify problems, and take corrective actions — so I can manage properties efficiently without manual investigation.

---

## Acceptance Criteria

- [ ] **Search works** — User types property name, gets autocomplete with 3 results (status + review rate) in < 1s
- [ ] **Property detail loads** — Click result → modal opens with health metrics, chart, cases, actions (< 500ms)
- [ ] **Performance scales** — 50 properties loaded without UI lag (virtualized grid, preload top 10)
- [ ] **RLS enforced** — Admin sees all, Assistant sees subset, Owner sees only their property (read-only)
- [ ] **Mobile responsive** — All features work on mobile (drawer-style modal, stacked grid)
- [ ] **Accessibility passes** — WCAG AA minimum (keyboard nav, focus management, color + text)
- [ ] **Tests cover critical flows** — E2E: search → detail → action; error handling

---

## Scope

### ✅ INCLUDED (Phase 1 - Lean)

**Backend APIs (3 new routes):**
- `GET /api/admin/sync/search?q={query}&limit=10` — Autocomplete search
- `GET /api/admin/sync/properties/{id}` — Property detail with metrics
- `GET /api/admin/sync/properties/{id}/cases?limit=50&offset=0` — Cases paginated

**Frontend Components:**
- SearchBar with autocomplete (debounce 300ms)
- PropertyCard (status badge, metrics, click-to-detail)
- PropertyDetailModal (metrics, chart, cases table, actions)
- FilterBar (Status, ErrorType, Period dropdowns)
- PropertyGrid with virtualization
- AlertBanner (critical properties)

**Key Features:**
- Search-first experience (< 5 sec to identify problem)
- Modal drill-down (non-destructive)
- Role-based UI (admin/assistant/owner)
- Chart (recharts) — 7/14/30 day history
- Infinite scroll + lazy-load (preload top 10)

**Testing:**
- E2E critical flows (search, detail, actions)
- Accessibility audit (axe DevTools)
- Performance testing (Core Web Vitals)
- Mobile responsiveness

---

### ❌ NOT INCLUDED (Phase 2)

- Resolution templates (automated fixes)
- WebSocket real-time updates
- Notification service (email/push)
- Bulk actions
- Template marketplace

---

## Dev Notes

**Architecture:** Search-first, modal drill-down, virtualized grid  
**Tech Stack:** React 18, TypeScript, Tailwind, shadcn/ui, React Query, Recharts, TanStack Virtual  
**Chart Library:** Recharts (standard React charts)  
**Performance:** Preload top 10 properties, lazy-load rest, virtualize grid (only render visible cards)  

**Key Decisions:**
1. Skip resolution templates → phase 2 (reduces scope by ~20 hours)
2. Virtualization from start → avoid performance cliff at 50 properties
3. RLS backend filtering → Admin sees all, Assistant sees subset, Owner sees own (read-only)

**Design Approved By:** Uma (UX Design Expert) — `/docs/specs/SYNC-DASHBOARD-FRONTEND-SPEC.md`

## Testing

### Unit Tests
- SearchBar: debounce behavior, autocomplete filtering, error states
- PropertyCard: click handler, role-based rendering
- FilterBar: filter state changes, URL sync
- StatusBadge: color mapping, accessibility

### E2E Tests (Cypress/Playwright)
1. **Search Flow:** Type "Casa" → results appear → click → modal opens
2. **Detail Flow:** Modal shows correct metrics/chart/cases
3. **Filter Flow:** Filter by status → grid updates correctly
4. **Error Flow:** API fails → error message + retry button appears
5. **Mobile Flow:** Drawer-style modal works on mobile

### Performance
- SearchBar autocomplete < 300ms debounce
- Property detail API < 500ms
- Modal open animation smooth (60fps)
- Grid scroll smooth (virtualization working)
- Core Web Vitals: LCP < 2.5s, FID < 100ms, CLS < 0.1

### Accessibility
- Keyboard navigation (Tab through buttons, Escape closes modal)
- Focus management (modal trap, return to trigger)
- Color contrast (WCAG AA: 4.5:1 for text)
- Screen reader labels (aria-labels on buttons)
