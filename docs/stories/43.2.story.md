# Story 43.2: Direct Booking Creation Page

**Depends On:**
- ✅ Story 43.1 (ReservationValidator)
- ✅ Story 43.1.1 (API integration tests)
- ✅ Story 43.1.2 (Overlap detection)

---

## Story

As an **admin managing a property**, I need to **create direct bookings manually** through the admin UI — so I can accept off-platform reservations and bypass the normal booking flow.

---

## Acceptance Criteria

- [ ] **Admin Direct Booking Page** — Create reservation form at `/admin/reservations/create`
  - Route: `src/app/[locale]/admin/reservations/create/page.tsx`
  - Auth: Admin-only (verify via Supabase RLS)
  - Success: Form renders with all inputs visible

- [ ] **Form Inputs** — Collect reservation data
  - Property selector (dropdown or autocomplete)
  - Guest name (text input, required)
  - Guest email (email input, required)
  - Check-in date (date input, required)
  - Check-out date (date input, required)
  - Guest count (number input, optional)
  - Notes (textarea, optional)
  - Price override (currency input, optional for manual pricing)

- [ ] **Validator Integration** — Call ReservationValidator before creating
  - Button "Criar Reserva" (create booking)
  - On click: POST to /api/admin/reservations/validate
  - Display validation results (price breakdown, discounts, warnings)
  - Show errors if validation fails (red box)
  - Show success summary if validation passes (green box)
  - Enforce the global and period-specific minimum stay configured in the calendar

- [ ] **Conditional Confirmation** — Show creation form only after validation passes
  - If validation fails → Block creation, show error
  - If validation passes → Show "Confirmar Reserva" button
  - On confirm: POST to /api/admin/reservations (create endpoint)
  - Return: Reservation ID + confirmation message

- [ ] **Create Reservation API** — POST endpoint for creating reservations
  - Route: `src/app/api/admin/reservations/route.ts`
  - Input: propertyId, checkIn, checkOut, guestName, guestEmail, guestCount, notes, finalPrice
  - Validation: Check overlap one more time (safety check)
  - Insert: reservations table with status='active'
  - Return: { success: boolean, reservationId: string, message: string }
  - Error handling: DB errors, validation failures

- [ ] **Success State** — Show confirmation after creation
  - Clear form
  - Show success message: "Reserva criada: RES-{ID}"
  - Show reservation details (property, dates, guest, price)
  - Button: "Nova Reserva" (reset form)

- [ ] **Unit Tests** — Form logic and API endpoint
  - Test form submission with valid data
  - Test validation error display
  - Test overlap detection prevents creation
  - Test successful reservation creation
  - Test error handling (DB failures, invalid property)

## Dev Notes

**Database Requirements:**
- `reservations` table with columns: id, property_id, guest_name, guest_email, guest_count, check_in, check_out, final_price, notes, status, created_at
- status = 'active' | 'cancelled' | 'completed'
- Index: reservations(property_id, check_in, check_out) ✅ (from 43.1.2)

**API Response Format:**
```typescript
// POST /api/admin/reservations/validate (existing, from 43.1)
{
  success: boolean
  nights: number
  price: { subtotal, finalPrice, currency }
  discount: { hasDiscount, discountPercentage, savings }
  minimumNights: { passed, error? }
  cancellationPolicy: { policyName, refundPercentage }
  errors: string[]
  warnings: string[]
}

// POST /api/admin/reservations (new, this story)
{
  success: boolean
  reservationId: string
  message: string
  error?: string
}
```

**UI Flow:**
```
Step 1: Fill Form
  → Property, Guest, Dates, Price

Step 2: Click "Validar Reserva"
  → POST /api/admin/reservations/validate
  → Display ValidationResult (price, discount, policy)
  → Show errors if any

Step 3: If valid, show "Confirmar Reserva" button
  → Click to proceed

Step 4: Click "Confirmar Reserva"
  → POST /api/admin/reservations (create)
  → Display reservation ID + success message
  → Reset form
```
