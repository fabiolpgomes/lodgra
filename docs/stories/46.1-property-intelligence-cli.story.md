# Story 46.1: Gerador CLI de Análise Previsional de Imóvel

**Epic:** Evolução Modular do Lodgra + MVP de IA Native para Viabilidade de Propriedades  
**Status:** Done  
**Owner:** @pm  
**Quality Gate:** @architect + @ux  
**Depends On:** none

## Product Intent

Criar o menor corte funcional do MVP de Property Intelligence dentro do Lodgra, começando por um motor CLI isolado, verificável e orientado a story.

O objetivo desta story não é criar interface, automação complexa ou agentes múltiplos. O objetivo é produzir uma análise previsional inicial a partir de dados fornecidos manualmente e com premissas explícitas.

## Story

**Como** gestor comercial,  
**Quero** fornecer os dados básicos de um imóvel e receber três cenários de exploração,  
**Para que** eu possa apresentar ao proprietário uma estimativa fundamentada de rentabilidade.

## Context

O Lodgra já possui uma estrutura extensa e funcional. Por isso, o MVP não deve criar uma arquitetura paralela nem assumir novos módulos genéricos sem antes analisar o que já existe.

Nesta primeira fase:
- o input será fornecido em JSON
- os cálculos serão determinísticos
- a saída deverá existir em JSON e Markdown
- a análise poderá ser aprovada manualmente antes de avançar para etapas mais automáticas
- o primeiro corte permanece CLI-first e stateless
- a persistência fica fora do corte inicial até a prova de valor

## Acceptance Criteria

### AC1: Input estruturado
- [x] Receber dados do imóvel por JSON
- [x] Aceitar lead, propriedade e premissas
- [x] Permitir campos desconhecidos como `null`

### AC2: Cálculo previsional
- [x] Calcular arrendamento tradicional
- [x] Calcular alojamento de média duração
- [x] Calcular alojamento local
- [x] Produzir cenários conservador, provável e otimista

### AC3: Saída legível
- [x] Apresentar receita bruta
- [x] Apresentar custos estimados
- [x] Apresentar resultado líquido
- [x] Mostrar todas as premissas usadas
- [x] Marcar claramente valores estimados

### AC4: Formatos de saída
- [x] Gerar saída em JSON
- [x] Gerar saída em Markdown
- [x] Não depender de interface gráfica

### AC5: Escopo controlado
- [x] Não usar IA para fazer os cálculos matemáticos
- [x] Não usar scraping automático
- [x] Não alterar a tabela operacional `properties`
- [x] Não criar automação multiagente nesta fase

## Scope

### In scope
- CLI de análise previsional
- leitura de input manual via JSON
- motor determinístico de cenários
- builder de relatório em Markdown
- output verificável e repetível

### Out of scope
- dashboard
- formulário sofisticado
- PDF
- scraping automático de Booking.com
- publicação direta para o proprietário
- alteração da tabela operacional `properties`

## Deliverables

- story base para o MVP Property Intelligence
- contrato de input JSON
- motor previsional determinístico
- relatório Markdown e JSON
- ponto de partida para arquitetura e implementação
