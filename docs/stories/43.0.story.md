# Epic 43: Sistema Completo de Calendário Administrativo e Configuração de Preços (Tipo Airbnb)

**Status:** Draft  
**Priority:** High  
**Complexity:** XXHIGH (Multi-Sprint Epic)  
**Target:** Full system redesign of pricing, availability, and cancellation policies

---

## Story

O Algarve Home Stay precisa de um sistema de calendário administrativo robusto que permita aos proprietários gerenciar preços, disponibilidade, descontos e políticas de cancelamento com flexibilidade total (por dia, período, ou regra global). 

O sistema deve:
- Oferecer visão Kanban desktop com layout tipo Airbnb
- Permitir configuração granular de preços (global, período, dia)
- Suportar múltiplos tipos de descontos (semanal, mensal, fidelidade)
- Impor políticas de disponibilidade (mín/máx noites, aviso prévio)
- Oferecer 4 tipos de política de cancelamento + opção não-reembolsável
- Calcular reservas com transparência total (preço × dias - descontos + taxas)
- Funcionar em desktop e mobile

### Card Preços
- [ ] Preço Base: campo de entrada + botão "Preencher Calendário"
- [ ] Após preencher, todas as datas do mês recebem este preço em `pricing_rules` (nova regra criada)
- [ ] Seleção de período no calendário → modal para personalizar preço
- [ ] Seleção de dia único → modal para preço do dia
- [ ] Preços Inteligentes: toggle on/off (não implementar lógica, apenas schema + UX)

- [ ] Preços salvos em `pricing_rules` com `start_date`, `end_date`, `price_per_night`

### Card Descontos
- [ ] Semanal: input percentual para 7+ noites (aplicado APENAS se noites < 28)
- [ ] Mensal: input percentual para 28+ noites (aplicado APENAS se noites >= 28)

- [ ] Cliente Fidelidade: input percentual adicional (aplicado em cascata, APÓS desconto de volume)
- [ ] Mostrar cálculos: "Média semanal = €894" (baseado no histórico de reservas)
- [ ] Descontos salvos em tabela `property_discounts` (criar se não existir)

### Card Disponibilidade
- [ ] Mínimo de noites: input numérico
- [ ] Máximo de noites: input numérico
- [ ] Aviso prévio: dropdown (Mesmo dia, 1 dia, 2 dias, 7 dias)
- [ ] Flag "Permitir pedidos com menos de 1 dia de aviso" (requer aprovação)
- [ ] Período de disponibilidade: dropdown (24m, 12m, 9m, 6m, 3m, Indisponíveis)
- [ ] Flag "Permitir pedidos além do período" (fica pendente até aprovação)
- [ ] Dados salvos em `property_availability` (pode reutilizar tabela existente)

### Card Cancelamentos

- [ ] Estadias Longas (28+ noites): selector entre Flexível, Moderada, Limitada, Firme
- [ ] Opção Rígida para longas: "Não reembolsável com desconto de 10%"

- [ ] Tooltip "Saiba Mais" com informações completas
- [ ] Dados salvos em `property_cancellation_policies` (criar se não existir)

### Interações no Calendário

### Lógica de Cálculo de Reserva
- [ ] Preço diário = valor em `daily_prices` (override) OU `pricing_rules` (período) OU `properties.base_price` (fallback)
- [ ] Se período exigir múltiplas regras: usar maior preço do período? Ou média? (Detalhar com PO)
- [ ] ⚠️ **Descontos de Volume (EXCLUSIVOS, não acumulativos):**
  - [ ] Se noites >= 28: Aplicar APENAS desconto Mensal
  - [ ] Senão se noites >= 7: Aplicar APENAS desconto Semanal
  - [ ] Senão: Sem desconto de volume
- [ ] Aplicar desconto cliente fidelidade se hóspede recorrente (baseado em `reservations.guest_email`)
  - [ ] Aplicado SOBRE o valor já descontado (desconto em cascata)
- [ ] Mostrar breakdown com cascata: 
  - [ ] Preço Base × Dias = Subtotal
  - [ ] Se aplicável: - Desconto Semanal OU Mensal (escolha baseada em noites)
  - [ ] Se fidelidade: - Desconto Fidelidade (% sobre valor já descontado)
  - [ ] + Taxas = TOTAL

## Database Changes Required

### New Tables
1. **property_discounts** (se não existir)
   ```sql
   CREATE TABLE property_discounts (
     id UUID PRIMARY KEY,
     property_id UUID REFERENCES properties(id),
     weekly_percent DECIMAL(5,2),
     monthly_percent DECIMAL(5,2),
     loyalty_percent DECIMAL(5,2),
     created_at TIMESTAMP,
     updated_at TIMESTAMP
   );
   ```

2. **property_cancellation_policies** (se não existir)
   ```sql
   CREATE TABLE property_cancellation_policies (
     id UUID PRIMARY KEY,
     property_id UUID REFERENCES properties(id),
     stay_type ENUM ('short', 'long'), -- < 28 noites vs >= 28 noites
     policy_type ENUM ('flexible', 'moderate', 'limited', 'firm', 'non_refundable'),
     full_refund_days INT, -- dias antes do check-in
     partial_refund_days INT,
     partial_refund_percent DECIMAL(5,2),
     non_refundable_discount DECIMAL(5,2), -- apenas se policy_type = 'non_refundable'
     is_active BOOLEAN DEFAULT TRUE,
     is_long_stay BOOLEAN, -- TRUE se para estadias 28+, FALSE se < 28
     created_at TIMESTAMP,
     updated_at TIMESTAMP
   );
   ```

3. **daily_prices** (já recriada na Sprint anterior, confirmar)
   ```sql
   CREATE TABLE daily_prices (
     id BIGSERIAL PRIMARY KEY,
     property_id UUID REFERENCES properties(id),
     date DATE NOT NULL,
     base_price DECIMAL(10,2) NOT NULL,
     created_at TIMESTAMP,
     updated_at TIMESTAMP,
     UNIQUE(property_id, date)
   );
   ```

### Modified Tables

   - Confirmar: `start_date`, `end_date`, `price_per_night`, `min_nights`

2. **property_availability** (verificar/expandir)
