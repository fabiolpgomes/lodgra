## Dev Notes

**Architect Feedback (from review 2026-08-08):**
- URL validation is CRITICAL — prevents false positives
- Add error tracking fields for better debugging
- Email-to-property auto-detection deferred to Phase 2

**Schema Enhancement:**
```sql
ALTER TABLE property_listings ADD COLUMN (
  last_sync_error TEXT NULL,
  sync_error_count INT DEFAULT 0
);
```

**Enhanced Repair Logic:**
1. Fetch listings where name IS NULL OR platform IS NULL
2. For each listing:
   - If `ical_url` exists: HEAD request (5s timeout)
   - If 2xx response: populate name (from property.name), platform (infer from domain or default to "Airbnb")
   - If failed: populate name, set `sync_enabled=false`, log error
3. Log repair summary: {updated: N, errors: M}

**URL Validation Strategy:**
- Airbnb: HEAD https://www.airbnb.com/calendar/...
- Booking: HEAD https://www.booking.com/calendar-ical/...
- Flatio: HEAD https://www.flatio.com/calendar/...
- Custom: HEAD {url} (assume valid if 2xx)

**Edge Cases:**
- No iCal URL: `sync_enabled = false`, error = "URL missing"
- Network timeout (>5s): `sync_enabled = false`, error = "Timeout validating URL"
- Invalid domain: `sync_enabled = false`, error = "Invalid URL format"
- SQL errors: Log and skip, don't block repair
