## 📖 Story

Como proprietário, quero definir políticas de cancelamento flexíveis ou rígidas (Airbnb model), e ter reembolsos automáticos processados via Stripe quando clientes cancelam, com base na política e data de cancelamento.

---

## ✅ Acceptance Criteria

### Database & Types
- [ ] Migration: Create `property_cancellation_policies` table
- [ ] Migration: Alter `reservations` table (add cancellation_policy_id, snapshot, refund_amount, stripe_refund_id)
- [ ] TypeScript: Create `src/types/cancellation.types.ts` with full types
- [ ] Enums: PolicyType (flexible, moderate, limited, firm, rigid), StayDuration (short <28, long >=28)

### Configuration UI
- [ ] 4ª tab "Cancelamentos" em SettingsSidebar (UI exists, make functional)
- [ ] CancellationCard component mostra:
  - **Estadias curta duração (<28 noites):** Flexível, Moderada, Limitada, Firme
  - **Estadias longa duração (28+ noites):** Flexível, Moderada, Limitada, Firme, Rígida
  - Opção non-refundable com toggle + desconto (e.g., -10%)
- [ ] Cada política tem:
  - Tipo
  - Duração da estadia
  - Períodos de reembolso (dias antes check-in)
  - Percentagens de reembolso
  - (Optional) Non-refundable discount %
- [ ] Proprietário pode editar políticas via modal
- [ ] Dados salvos via `POST/PUT /api/properties/[id]/cancellation-policies`

### Refund Logic (Core)
- [ ] Criar `src/lib/cancellation/refund-calculator.ts`:
  - Input: policy_type, stay_duration, days_until_checkin, during_stay
  - Output: refund_percentage (0-100%)
  - Logic (Airbnb-exact):
    - **Flexível:** 100% até 1 dia antes → 50% até 1 dia após checkin
    - **Moderada:** 100% até 5 dias antes → 50% até 5 dias após checkin
    - **Limitada:** 100% até 14 dias antes → 50% (7-14 dias antes)
    - **Firme:** 100% até 30 dias antes → 50% (7-30 dias antes)
    - **Rígida (long-stay only):** Non-refundable (0%)
    - **Non-refundable option:** 0% (com desconto na tarifa)

### Reservation Integration
- [ ] Quando reserva é criada:
  - Determinar duração (check_out - check_in)
  - Selecionar política apropriada (short/long)
  - Gravar `cancellation_policy_id` e `cancellation_policy_snapshot` (JSONB) na reserva
  - Snapshot contém valores completos da política para auditoria

### Cancellation Flow
- [ ] Quando cliente cancela reserva (via CancelReservationButton):
  - Recuperar política da reserva
  - Calcular dias até check-in
  - Chamar refund_calculator → obter refund_percentage
  - Calcular refund_amount = reservation.total_amount × (refund_percentage / 100)
  - **Processar refund automático via Stripe:**
    - Call `/api/billing/refunds` com calculated amount
    - Gravar `stripe_refund_id` na reserva
    - Atualizar status → `cancelled`
    - Gravar `refund_processed_at`
  - Enviar email ao cliente (ver template em `src/lib/email/refund-processed.ts`)

### Validation & Error Handling
- [ ] Impedir cancelamento após período de cancelamento gratuito
- [ ] Validar refund_amount não exceda original payment
- [ ] Stripe error → log + retry logic (exponential backoff)
- [ ] Mostrar "Refund will be processed within 5-7 business days" ao cliente

## 🔄 Dev Notes

### Policy Selection Logic
```typescript
// On reservation creation:
const nightCount = (checkOut - checkIn).days;
const stayDuration = nightCount >= 28 ? 'long' : 'short';
const policy = await getDefaultPolicyForProperty(propertyId, stayDuration);
// Save to reservation.cancellation_policy_id
```

### Refund Calculation
```typescript
const daysUntilCheckIn = (checkIn - today).days;
const isAfterCheckIn = today > checkIn;
const refund% = policy.calculate_refund({
  days_before: daysUntilCheckIn,
  during_stay: isAfterCheckIn,
  stay_duration: stayDuration
});
```

### Snapshot Rationale
Policies can change over time. Storing snapshot ensures refund calculation is accurate for the exact policy that was active at booking time (historical audit trail).
