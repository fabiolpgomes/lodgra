## Dev Notes

**Architecture Decisions (from review 2026-08-08):**
- Email enriches iCal (not vice versa)
- Deduplication by external_id prevents duplicates
- Auto-detection by domain ensures property mapping without user config

**Email Domain Mapping:**
```
airbnb.com → platform: "Airbnb"
booking.com → platform: "Booking"
flatio.com → platform: "Flatio"
```

**Matching Strategy:**
1. Extract check_in, check_out from email
2. Find reservations in property with overlapping dates
3. Score by: date match (100% if exact) + guest name similarity (80%+)
4. Return highest scoring match or NULL

**Cancellation Keywords:**
- English: cancel, refund, void, declined, failed
- Portuguese: cancelar, cancelada, reembolso, recusado, falhou, não confirmado

**Edge Cases:**
- Email without property match → log & skip (don't create reservation)
- Multiple properties with same platform → pick first (or use ical_url matching)
- Email with date but no guest name → match by date only (risky, score lower)
- Reservation with multiple emails from same guest → enrich with latest data
