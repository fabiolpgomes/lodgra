# Story 43.1.2: Overlapping Reservation Detection

**Parent Story:** 43.1 (Direct Booking Reservation Validator)

**Reference:** `docs/qa/QA_FIX_REQUEST-43.1.md` (Item 2)

## Story

As an **admin creating a manual reservation**, I need to **detect if the proposed dates overlap with existing reservations** — so I can prevent double-booking conflicts.

---

## Acceptance Criteria

- [ ] **Overlap Detection Method** — Add validateReservationOverlap() to ReservationValidator
  - Input: propertyId, checkIn, checkOut, excludeReservationId (optional)
  - Query: Find all active reservations with overlapping dates
  - Return: { hasConflict: boolean, conflictingReservations: [...] }
  - Overlap logic: check_in < checkOut AND check_out > checkIn

- [ ] **Orchestrator Integration** — Add overlap check to validate() method
  - Call validateReservationOverlap() in parallel with other validations
  - Add conflicts to errors array if found
  - Message format: "Overlapping reservations found: {id1}, {id2}, ..."

- [ ] **Database Query** — Implement Supabase query for date range conflict
  - Query: SELECT * FROM reservations WHERE property_id = ? AND status != 'cancelled'
  - Filter: (check_in < ? AND check_out > ?) OR (check_in = ? AND check_out = ?)
  - Exclude: excludeReservationId if provided (for edit scenarios)
  - Performance: Index on reservations(property_id, check_in, check_out)

- [ ] **Unit Tests** — Test overlap detection logic
  - Test: No overlap (dates after/before)
  - Test: Exact overlap (same dates)
  - Test: Partial overlap (starts during, ends after)
  - Test: Contained within (starts after, ends before)
  - Test: Exclude reservation ID (for edit mode)
  - Test: Ignore cancelled reservations
  - Acceptance: All 6 scenarios passing

- [ ] **Integration Tests** — Test API endpoint with overlaps
  - Test: Valid dates with no overlap → success
  - Test: Dates with active reservation → error + conflicting IDs
  - Test: Dates overlap but reservation cancelled → success
  - Acceptance: All 3 scenarios passing

## Dev Notes

**Overlap Detection Logic:**
```typescript
// Two date ranges overlap if:
// range1.start < range2.end AND range1.end > range2.start

// Examples:
// [2026-08-05 to 2026-08-10] vs [2026-08-08 to 2026-08-12] → OVERLAP
// [2026-08-05 to 2026-08-10] vs [2026-08-10 to 2026-08-15] → NO OVERLAP (end = start)
// [2026-08-05 to 2026-08-10] vs [2026-08-03 to 2026-08-05] → NO OVERLAP (end = start)
```

**Database Requirements:**
- `reservations` table with: id, property_id, check_in, check_out, status
- Status values: 'active', 'cancelled', 'completed'
- Filter: status != 'cancelled' (ignore cancelled bookings)
- Index: reservations(property_id, check_in, check_out) for query performance
