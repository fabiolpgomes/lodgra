# Story 43.1: Direct Booking Reservation Validator

## Story

As an **admin creating a manual reservation**, I need to **validate the reservation details** (price, discounts, minimum nights, cancellation policy) before confirming — so I can ensure accuracy and compliance with property rules.

---

## Acceptance Criteria

- [ ] **Price Validation** — System fetches correct price for check-in/checkout period
  - Validate: Price is applied from calendar configuration for exact dates
  - Handle: Partial days (check-in same day, checkout same day)
  - Show: Price breakdown by day/period

- [ ] **Discount Validation** — System checks if period qualifies for discounts
  - Rule: 7-27 days → Apply minimum discount (configured per property)
  - Rule: 28+ days → Apply extended stay discount (configured per property)
  - Show: Discount percentage + final price after discount
  - Handle: No discount if < 7 days

- [ ] **Minimum Nights Validation** — System checks property's minimum night requirement
  - Validate: Reservation length >= property's min_nights_configured
  - Show: "❌ This property requires minimum {X} nights. You selected {Y} nights"
  - Allow: Override if admin role (with warning)

- [ ] **Cancellation Policy Validation** — System shows applicable cancellation policy
  - Fetch: Cancellation policy associated with check-in date
  - Show: Policy name + terms (refund %, deadline)
  - Handle: Multiple policies by date range

- [ ] **Validation API** — POST endpoint for manual validation
  - Input: propertyId, checkIn, checkOut, guestCount
  - Output: ValidationResult with all checks + final price
  - Error handling: Invalid property, past dates, overlapping reservations

- [ ] **Unit Tests** — All validations covered
  - Test price calculation for various date ranges
  - Test discount logic (7 days, 28+ days, no discount)
  - Test minimum nights validation
  - Test cancellation policy lookup
  - Test error cases

- [ ] **Integration Tests** — End-to-end validation flow
  - Test API endpoint with mock data
  - Test database queries (pricing, policies)
  - Test error responses

## Dev Notes

**Architecture:** Static validator class + API endpoint + React form  
**Tech Stack:** React, TypeScript, Next.js API routes, Supabase  

**Key Validations:**
1. Price lookup from calendar pricing table
2. Discount calculation (7-27 days vs 28+ days)
3. Minimum nights check from property config
4. Cancellation policy lookup by date range

**Database Queries Needed:**
- `calendar_pricing` — Daily prices by property/date
- `property_discounts` — Discount rules (7-27 days, 28+ days)
- `properties` — min_nights_configured
- `cancellation_policies` — Policy by property/date range
- `reservations` — Check for conflicts (future phase)

**Error Scenarios:**
- Property not found
- Check-out before check-in
- Past dates
- Invalid guest count
- No pricing configured for dates
- Multiple overlapping policies (use earliest)

## Validation Scenarios

### Scenario 1: 5-night stay (no discount)
```
Property: Casa Moinho
Check-in: 2026-08-05
Check-out: 2026-08-10 (5 nights)
Min nights: 2 ✅
Price/night: €100
Discount: None (< 7 days)
Result: €500 total
Cancellation policy: Standard (50% up to 7 days)
```

### Scenario 2: 10-night stay (7-day discount)
```
Property: AHS Premium
Check-in: 2026-08-05
Check-out: 2026-08-15 (10 nights)
Min nights: 3 ✅
Price/night: €80 (avg)
Discount: 10% (7-27 days)
Base: €800 → Final: €720
Cancellation policy: Flexible (75% up to 3 days)
```

### Scenario 3: 30-night stay (extended discount)
```
Property: Casa Típica
Check-in: 2026-08-01
Check-out: 2026-08-31 (30 nights)
Min nights: 5 ✅
Price/night: €60
Discount: 20% (28+ days)
Base: €1800 → Final: €1440
Cancellation policy: Strict (no refund after 14 days)
```

### Scenario 4: Error — too few nights
```
Property: Luxury Apartment
Check-in: 2026-08-05
Check-out: 2026-08-06 (1 night)
Min nights: 5 ❌
Error: "This property requires minimum 5 nights"
Action: Admin can override with warning
```
