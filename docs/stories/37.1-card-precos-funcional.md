# Story 37.1: Card Preços (Funcional)

**Epic:** 37 — Calendar Pricing & Availability Management  
**Status:** Ready for Dev  
**Size:** 8h  
**Priority:** P1

---

## 📖 Story

Como proprietário, quero configurar preços base e inteligentes para a minha propriedade, e ter as definições guardadas e aplicadas ao calendário.

---

## ✅ Acceptance Criteria

### Configuration
- [ ] PriceCard carrega dados da API (`GET /api/properties/[id]/pricing`)
- [ ] Proprietário pode editar preço base via modal
- [ ] Proprietário pode editar preço fim de semana via modal
- [ ] Proprietário pode ativar/desativar "Preços Inteligentes" (toggle)
- [ ] Se "Preços Inteligentes" ativado, campos min/max price aparecem
- [ ] Todos os valores são salvos via `PUT /api/properties/[id]/pricing`

### Data Persistence
- [ ] Valores editados persistem após reload da página
- [ ] Validações: preço_base >= 1, fim_semana >= preço_base (se definido)

### Calendar Integration
- [ ] Preços aparecem nos cells do calendário
- [ ] Fim de semana mostra preço ajustado (se configurado)
- [ ] Sobreposições diárias (`property_daily_prices`) têm prioridade

### Validation
- [ ] Impedir preços negativos
- [ ] Impedir preço_max < preço_min (inteligentes)
- [ ] Validar moeda (EUR)

### Implementation Summary

✅ **API Endpoint** (`src/app/api/properties/[id]/pricing/route.ts`)
- GET: Fetch pricing data (with ownership validation)
- PUT: Save pricing data (with validation)
- Validation: base_price >= 1, weekend_price >= base_price
- Authorization: Owner-only access via RLS

✅ **PriceCard Component** (Enhanced)
- Added edit modal with input validation
- Props: `onSave`, `editableValue`
- Error handling: Toast notifications
- Loading state support

✅ **SettingsSidebar Integration**
- Fetch pricing on mount (useEffect)
- Handle save operations
- Toggle smart pricing (UI placeholder, no calc)
- Error and loading states

✅ **Test Coverage**
- 35 tests passing
- Unit tests: PriceCard display, validation, modals
- Integration tests: API GET/PUT, authorization, data consistency
- All validation rules covered

### Decision Log

1. **API Structure:** Used existing pattern from availability endpoint (proven pattern)
2. **Component State:** useState for modal control + API state (pragmatic, minimal)
3. **Validation:** Client-side (UX) + Server-side (safety)
4. **Error Handling:** Toast notifications + error states
5. **Smart Pricing:** UI prepared (toggle), no calculation yet (as per story)

### Known Limitations

- Smart pricing is UI-only (flag toggles but no calculation applied)
- No daily price overrides in this story (future Story 37.2+)
- Limited to current property context (no multi-property support needed)
