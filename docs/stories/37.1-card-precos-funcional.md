## 📖 Story

Como proprietário, quero configurar preços base e inteligentes para a minha propriedade, e ter as definições guardadas e aplicadas ao calendário.

## ✅ Acceptance Criteria

### Configuration
- [ ] PriceCard carrega dados da API (`GET /api/properties/[id]/pricing`)
- [ ] Proprietário pode editar preço base via modal
- [ ] Proprietário pode editar preço fim de semana via modal
- [ ] Proprietário pode ativar/desativar "Preços Inteligentes" (toggle)
- [ ] Se "Preços Inteligentes" ativado, campos min/max price aparecem
- [ ] Todos os valores são salvos via `PUT /api/properties/[id]/pricing`

### Data Persistence
- [ ] Valores editados persistem após reload da página
- [ ] Validações: preço_base >= 1, fim_semana >= preço_base (se definido)

### Calendar Integration
- [ ] Preços aparecem nos cells do calendário
- [ ] Fim de semana mostra preço ajustado (se configurado)
- [ ] Sobreposições diárias (`property_daily_prices`) têm prioridade

### Validation
- [ ] Impedir preços negativos
- [ ] Impedir preço_max < preço_min (inteligentes)
- [ ] Validar moeda (EUR)

## 🚨 QA Results (Reviewed 2026-08-02)

**Gate Decision:** FAIL ❌

### Critical Issues

**1. CRITICAL: AC #3 Not Implemented**
- Acceptance Criteria #3 states: "Proprietário pode editar preço fim de semana via modal"
- PriceCard component has NO weekend price editing UI
- API supports weekend_price but component never displays/edits it
- Status: BLOCKING PASS

**2. HIGH: API Authentication Gap**
- Both GET and PUT endpoints at `/api/properties/[id]/pricing` lack user authentication
- No verification that current user is property owner
- Uses admin client (bypasses RLS) without explicit ownership checks
- Other endpoints use `requireRole()` pattern; this doesn't
- Risk: Any authenticated user could access/modify pricing for any property

**3. MEDIUM: Bulk-Update Security Gap**
- POST `/api/properties/[id]/pricing/bulk-update` missing ownership verification
- Uses admin client without explicit owner check
- RLS policies bypassed

### Test Coverage Issues

- Tests contain only mock assertions (e.g., `expect(401).toBe(401)`) not real HTTP tests
- No tests verify authorization actually works
- Weekend price tests missing (feature doesn't exist)
- Authorization boundary tests missing

### What's Working ✅

- Base price editing: ✅ Functional
- API GET/PUT mechanics: ✅ Working
- Validation rules: ✅ Correct (base >= 1, weekend >= base)
- Database persistence: ✅ Correct
- Lint/TypeCheck: ✅ Pass
- Regressions: ✅ None (2702 tests passing)
- Code quality: ✅ Good patterns
