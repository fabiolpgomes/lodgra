## 📋 Overview

Story 44.2 Phase 2 implements a **3-stage automated synchronization pipeline** that:
1. **Job 1 (sync-ical):** Synchronizes reservations from iCal feeds every 15 minutes
2. **Job 2 (email-parser):** Reads and normalizes incoming OTA emails every 15 minutes
3. **Job 3 (enrich-reservations):** Enriches existing reservations with email data every 15 minutes

All jobs run automatically via **Supabase pg_cron** with a real-time monitoring dashboard.

---

## 🏗️ Architecture

### System Overview

```
iCal Feeds (Airbnb, Booking, etc.)
    ↓
[pg_cron every 15m]
    ↓
Job 1: sync-ical (/api/cron/sync-ical)
    ↓
[Creates base reservations]
    ↓
Email Ingest (reservations@booking.com, etc.)
    ↓
Job 2: email-parser (/api/cron/email-parser)
    ↓
[Parses with Claude AI, detects property]
    ↓
[pg_cron every 15m]
    ↓
Job 3: enrich-reservations (/api/cron/enrich-reservations)
    ↓
[Matches + updates reservation fields]
    ↓
✅ Complete Reservation with email data
```

### Job Dependencies

```
email → email_parse_log
           ↓
        property_id (detected)
           ↓
        reservation_id (linked)
           ↓
    reservations table
           ↓
    ✅ (first_name, last_name, number_of_guests, amount)
```

## 📦 Database Schema

### sync_logs table

```sql
CREATE TABLE sync_logs (
  id UUID PRIMARY KEY,
  property_listing_id UUID REFERENCES property_listings(id),
  sync_type TEXT, -- 'ical' | 'email'
  direction TEXT, -- 'inbound' | 'outbound'
  status TEXT, -- 'success' | 'failed'
  error_message TEXT,
  records_processed INTEGER,
  records_created INTEGER,
  records_updated INTEGER,
  records_failed INTEGER,
  synced_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT now()
);

CREATE INDEX idx_sync_logs_type ON sync_logs(sync_type);
CREATE INDEX idx_sync_logs_status ON sync_logs(status);
CREATE INDEX idx_sync_logs_synced_at ON sync_logs(synced_at DESC);
```

### email_parse_log table

```sql
CREATE TABLE email_parse_log (
  id UUID PRIMARY KEY,
  email_id TEXT UNIQUE,
  platform TEXT, -- 'booking' | 'airbnb' | 'flatio' | 'unknown'
  property_id UUID REFERENCES properties(id),
  parsed_data JSONB, -- { guest_name, checkin_date, amount, ... }
  reservation_id UUID REFERENCES reservations(id),
  status TEXT, -- 'pending' | 'enriched' | 'error'
  error_message TEXT,
  created_at TIMESTAMP DEFAULT now()
);
```

## 🚀 API Endpoints

### Job 1: sync-ical
**Endpoint:** `GET /api/cron/sync-ical`  
**Auth:** `Authorization: Bearer {CRON_SECRET}`
**Runs:** Every 15 minutes (pg_cron)

**Logic:**
1. Fetch property listings where:
   - `property_listings.is_active = true`
   - `properties.is_active = true`
   - `sync_enabled = true`
   - `ical_url IS NOT NULL`
2. Import events from iCal feed
3. Classify: Reservation vs Block
4. Create/update reservations in DB
5. Log to sync_logs

**Response:**
```json
{
  "message": "Sincronizados 18 anúncios",
  "synced": 18,
  "results": {
    "property-id-1": { "created": 2, "updated": 0, "skipped": 0 },
    "property-id-2": { "created": 1, "updated": 3, "skipped": 0 }
  }
}
```

### Job 2: email-parser
**Endpoint:** `GET /api/cron/email-parser`
**Auth:** `Authorization: Bearer {CRON_SECRET}`
**Runs:** Every 15 minutes (pg_cron)

**Logic:**
1. Read unprocessed OTA messages from the configured mailbox
2. Parse guest, stay and booking details
3. Resolve the tenant property
4. Persist normalized data in `email_parse_log`

### Job 3: enrich-reservations
**Endpoint:** `GET /api/cron/enrich-reservations`  
**Auth:** `Authorization: Bearer {CRON_SECRET}`
**Runs:** Every 15 minutes (pg_cron)

**Logic:**
1. Fetch unparsed emails from `email_parse_log` where:
   - `status != 'enriched'`
   - `parsed_data IS NOT NULL`
   - `property_id IS NOT NULL`
   - `reservation_id IS NOT NULL`
2. Match email to reservation by `reservation_id`
3. Extract first_name, last_name, num_guests, amount
4. Update reservations table
5. Mark email as enriched

**Response:**
```json
{
  "enriched": 5,
  "skipped": 2,
  "errors": 0,
  "errorDetails": []
}
```

### Admin: sync-logs
**Endpoint:** `GET /api/admin/sync-logs?limit=50`  
**Purpose:** Fetch recent sync activity for dashboard  
**Returns:** Array of sync_logs with property names enriched

## 🛠️ Implementation Details

### Job 1: sync-ical (src/app/api/cron/sync-ical/route.ts)

**Key Features:**
- iCal import via `importICalFromUrl()`
- Event classification: Reservation vs Block (duration, title patterns)
- Guest data extraction (Airbnb, Booking, Flatio formats)
- Conflict detection (overlap check with existing reservations)
- Service fee calculation
- Parallel processing by property (serial within property)

**Filtering:**
```typescript
const activeListings = (listings || []).filter((listing: any) => {
  const props = listing.properties
  return props?.is_active === true
})
```
Only syncs from **active properties** (prevents inactive listings)

### Job 2: email-parser (src/app/api/cron/email-parser/route.ts)

- Polls and parses OTA emails
- Requires the shared fail-closed cron Bearer authentication
- Stores normalized parsing results for the enrichment stage

### Job 3: enrich-reservations (src/app/api/cron/enrich-reservations/route.ts)

**3-Phase Workflow:**

**Phase 1: Fetch Emails**
```typescript
const { data: emails } = await supabase
  .from('email_parse_log')
  .select('id, platform, property_id, parsed_data, reservation_id')
  .not('property_id', 'is', null)
  .not('parsed_data', 'is', null)
  .not('reservation_id', 'is', null)
  .not('status', 'eq', 'enriched')
```

**Phase 2: Match Reservation**
- Use pre-linked `reservation_id` from email_parse_log
- No scoring needed (direct match)

**Phase 3: Update Fields**
```typescript
const updates = {
  first_name: parsed.guest_name.split()[0],
  last_name: parsed.guest_name.split().slice(1).join(' '),
  number_of_guests: parsed.num_guests,
  amount: parsed.amount,
  currency: parsed.currency || 'EUR',
  email_enriched_at: new Date().toISOString()
}
```

### Email Parser (src/lib/email-parser/parser.ts)

**Model:** Claude Haiku 4.5 (cost-optimized)  
**Input:** Raw email body (first 6000 chars)  
**Output:** Structured JSON

**Extraction Fields:**
- `guest_name` - Full name from email
- `checkin_date` - YYYY-MM-DD format
- `checkout_date` - YYYY-MM-DD format
- `amount` - Numeric value
- `currency` - EUR, USD, BRL, GBP
- `platform` - airbnb, booking, flatio, unknown
- `property_name` - Extracted property identifier
- `confirmation_code` - Booking reference
- `num_guests` - Guest count
- `discount_amount` - Optional discount

**Fallback:** If Claude misses dates, regex extraction from Portuguese date patterns

## 🔄 Data Flow Example

### Scenario: Airbnb Reservation + Email Confirmation

**T=0 (Airbnb iCal sync)**
```
iCal Event:
  uid: Yz04M4...@airbnb.com
  summary: "Reserved"
  start: 2026-08-20
  end: 2026-08-25
  description: "Guest John Doe"
  ↓
[Job 1 runs]
  ↓
CREATE reservations {
  external_id: "airbnb-Yz04M4...",
  property_listing_id: "cc576a14-...",
  check_in: 2026-08-20,
  check_out: 2026-08-25,
  guest_name: "John Doe",  ← from iCal
  status: "confirmed",
  created_at: 2026-08-09 12:00:00
}
```

**T=+5min (Email arrives)**
```
Email:
  from: reservations@airbnb.com
  subject: "Your booking is confirmed - 456123"
  body: "Dear John, Your stay at Casa da Praia..."
  ↓
[Job 2 parses email]
  ↓
INSERT email_parse_log {
  platform: "airbnb",
  property_id: "cc576a14-...",  ← detected
  parsed_data: {
    guest_name: "John Doe",
    checkin_date: "2026-08-20",
    checkout_date: "2026-08-25",
    amount: 450,
    currency: "EUR",
    confirmation_code: "456123"
  },
  reservation_id: "res-abc123",  ← matched
  status: "pending"
}
```

**T=+15min (Enrichment runs)**
```
[Job 3 runs]
  ↓
UPDATE reservations SET {
  first_name: "John",
  last_name: "Doe",
  amount: 450,
  currency: "EUR",
  email_enriched_at: 2026-08-09 12:15:00

UPDATE email_parse_log SET status = "enriched"
```

## 📝 Troubleshooting

### "Propriedade não ativa aparecendo na sincronização"
**Cause:** Property is_active = false but still being synced  
**Fix:** Check filter in Job 1:
```typescript
const activeListings = listings.filter(l => l.properties.is_active === true)
```
**Verify:** `SELECT * FROM properties WHERE name LIKE '%search%' AND is_active = false;`

### "0 criadas, 0 atualizadas — está tudo ok?"
**Cause:** Ambiguous status message  
**Fix:** Dashboard now shows:
- "Sem novidades" (0/0) = Normal, no new reservations
- "5 nova(s), 0 atualizada(s)" = Created 5 new

### "Email não está sendo enriquecido"
**Cause:** reservation_id não foi detectado no email_parse_log  
**Fix:** 
1. Verify email foi parseado: `SELECT * FROM email_parse_log WHERE status = 'pending';`
2. Check property_id foi detectado
3. Verify matching reservation exists:
   ```sql
   SELECT * FROM reservations 
   WHERE property_listing_id = ? 
   AND check_in = ? 
   AND check_out = ?;
   ```

### "Job não está rodando"
**Cause:** pg_cron job crashed or disabled  
**Fix:**
```sql
-- Check job status
SELECT * FROM cron.job;

-- View job logs
SELECT * FROM cron.job_run_details 
ORDER BY start_time DESC 
LIMIT 5;

-- Reschedule if needed
SELECT cron.alter_job('sync-ical-job', schedule := '*/15 * * * *');
```
